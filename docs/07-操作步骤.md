# 07-操作步骤

**是什么**：从零启动到出数、对账的完整操作手册。

**干什么**：把「先跑什么、后跑什么」写成 7 个阶段，每个阶段给出可直接复制的命令、预期输出、失败时看哪里。

**怎么用**：第一次搭建看阶段 0~1；日常启动看阶段 2~3；每天跑批看阶段 4~5；改完代码或出问题看阶段 6~7。

> 本文只写「怎么跑」。为什么这样设计看 04-架构设计，表结构和口径看 03-数据模型，指标定义看 02-指标体系，对账规则看 06-数据质量与对账。

## 零、前置说明

**执行环境**：WSL2 Ubuntu，用户 `hzh`，仓库在 `/mnt/d/projects/ecommerce-realtime-dw`。所有 `scripts/*.sh` 内部都会先 `cd` 到仓库根，所以在哪个目录执行都可以，但下文默认你在仓库根。

**密码规则**：MySQL 口令只走环境变量 `MYSQL_PASSWORD` 或命令行参数；CDC 密码只在 `run_j1.sh` 执行时通过参数传入，脚本用临时文件替换占位符、提交后立即删除；Doris root 免密。仓库里不出现任何明文口令。

**PowerShell 注意**：不要在 PowerShell 里拼长的 `wsl bash -c "... mysql -e \"...\""`，引号会被拆坏。把命令写进 `.sh` 文件，再 `wsl.exe -d Ubuntu -u hzh bash /mnt/d/.../x.sh`。

## 阶段 0：环境初始化（一次性）

**目的**：把 7 张 MySQL 表、5 个 Kafka topic、14 张 Doris 表、10 张 Hive 表建好，并把 Flink 集群拉起来。

**前置**：MySQL / Hive / HDFS / Kafka / Doris / Flink / Spark 均已安装。

### 0.1 MySQL 业务库与 CDC 账号

```bash
cd /mnt/d/projects/ecommerce-realtime-dw
sed 's/__CDC_PASSWORD__/你的CDC密码/g' sql/01_init_trade.sql | mysql -uroot -p
```

**预期**：`trade` 库 7 张表（`shop_info`、`user_info`、`product_info`、`order_info`、`order_detail`、`payment_info`、`refund_info`），并创建 `cdc` 账号、授予 `SELECT/RELOAD/REPLICATION SLAVE/REPLICATION CLIENT`。

**失败时**：MySQL 必须开启 binlog 且为 ROW 格式；否则 J1 启动时报 `SHOW MASTER STATUS` 或 `Access denied`。

### 0.2 Flink 集群

```bash
bash scripts/start_flink.sh      # 带 Hadoop classpath 起 1 JM + 1 TM
bash scripts/install_cdc.sh      # 仅重装/升级 CDC 连接器时执行
bash scripts/tune_flink.sh       # 设槽位与内存，需重启集群生效
```

**预期**：`curl -s 127.0.0.1:8081/overview` 返回 JSON，`taskmanagers=1`、`slots-total` 与 `tune_flink.sh` 设置一致。

**失败时**：WSL 会话退出会让 JM/TM 被回收，长期运行时用 `bash scripts/flink_keepalive.sh` 保活。

### 0.3 Kafka topic

```bash
bash scripts/init_kafka_topics.sh
```

**预期**：最后打印 5 个 topic：

```text
ods_order           3 分区
ods_order_detail    3 分区
ods_payment         3 分区
ods_refund          3 分区
ods_traffic         6 分区
```

**注意**：分区数一次定死，改分区会打乱 `key → partition` 映射，同一订单的变更可能落到不同分区而乱序。

### 0.4 Doris 表

```bash
bash scripts/init_doris.sh
```

**预期**：`dw` 库 14 张表：

| 类别 | 表 |
|---|---|
| 维表（2） | `dim_shop`、`dim_product` |
| 交易 DWD（1） | `dwd_trade_order_detail` |
| 交易 DWS（3） | `dws_trade_1min`、`dws_trade_shop_1h`、`dws_trade_product_1h` |
| 流量 DWD / 质量（2） | `dwd_traffic_detail`、`dwd_dirty_record` |
| 流量 DWS（2） | `dws_traffic_1min`、`dws_user_1d` |
| ADS（3） | `ads_gmv_realtime`、`ads_conversion_funnel`、`ads_topn_product` |
| 对账（1） | `ads_reconcile_diff` |

校验命令：

```bash
mysql -h127.0.0.1 -P9030 -uroot -e "SHOW TABLES FROM dw;"
```

### 0.5 Hive 表

```bash
export JAVA_HOME=/usr/lib/jvm/java-11-openjdk-amd64
/home/hzh/apps/spark/bin/spark-sql -f sql/09_init_hive.sql
```

**预期**：建 4 个库 `ods` / `dwd` / `dws` / `ads`，共 10 张表：

- `ods`：`order_info`、`order_detail`、`shop_info`、`user_info`、`product_info`
- `dwd`：`dwd_trade_order_detail`、`dwd_payment_detail`、`dwd_refund_detail`
- `dws`：`trade_1d`
- `ads`：`trade_recon_1d`

校验：

```bash
/home/hzh/apps/spark/bin/spark-sql -e "SHOW TABLES IN ads;"
```

**失败时**：Spark 连 Hive metastore 报 schema 版本不一致，确认 `hive-site.xml` 里 `metastore.schema.verification=false`；JDK 必须是 11（不是 17）。

## 阶段 1：造数与维表装载

**目的**：让 MySQL 有维表、有历史单，让 Doris 有维表快照，后续 CDC 和 Lookup 才有数据可用。

**前置**：阶段 0 全部完成。

**顺序不能换**：`master` 必须最先跑，它生成 `generator/id_pool.json`，后面三个生成器都依赖它。

### 1.1 维表与 ID 池

```bash
bash scripts/run_gen_master.sh 'MySQL口令'
```

**预期**：`shop_info` / `user_info` / `product_info` 三表有数，`generator/id_pool.json` 生成。

### 1.2 30 天历史订单

```bash
bash scripts/run_gen_history.sh 'MySQL口令'
```

**预期**：`order_info` / `order_detail` / `payment_info` 有约 90 万行历史数据（30 天）。

**注意**：这些历史单**不会**进入实时链路（J1 用 `latest-offset` 跳过历史），只供离线跑批和压测取数。

### 1.3 装载 Doris 维表

```bash
bash scripts/load_dim_shop.sh 'MySQL口令'
bash scripts/load_dim_product.sh 'MySQL口令'
```

**预期**：每个脚本打印 `导出行数` 和 Stream Load 的成功 JSON，最后打印 Doris 侧行数与抽样 3 行。

**失败时**：先看 Stream Load 返回 JSON 的 `Status` / `Message` / `ErrorURL`。401 是漏了 `-u`；`no valid Basic authorization` 是缺 `-L --location-trusted`。

## 阶段 2：启动实时链路

**目的**：把 binlog 和埋点变成 Doris 里的 DWD/DWS 数据。

**前置**：阶段 0.3 / 0.4 完成，阶段 1.1、1.3 完成（Lookup 需要维表），Flink 在跑。

**顺序**：J1 先起（否则下游没数据），J2~J5 无相互依赖，可以连着提交。

### 2.1 J1：CDC → Kafka

```bash
bash scripts/run_j1.sh 'CDC密码'
```

**预期**：Flink UI 出现 **4 个** 作业（`pipeline.name` 都是 `J1-cdc2kafka`），状态 `RUNNING`。4 个文件里的 4 条 `INSERT` 各提交一个作业。

### 2.2 J2~J5：DWD / DWS

```bash
bash scripts/run_j2.sh
bash scripts/run_j3.sh
bash scripts/run_j4.sh
bash scripts/run_j5.sh
```

**预期**：每个脚本提交 **1 个** 作业（文件里用 `EXECUTE STATEMENT SET` 把多条 INSERT 合成一个 DAG）。加上 J1 共 **8 个** Flink 作业，全部 `RUNNING`。

### 2.3 检查作业状态

```bash
bash scripts/check_flink.sh
```

**预期**：8 个作业 `RUNNING`，没有 `RESTARTING` / `FAILED`。

**失败时**：先 `bash scripts/last_job_error.sh`，再看 `job_stack.sh`；CDC 相关报错用 `cdc_stack.sh`。

### 2.4 开始造数（另开两个终端）

```bash
# 终端 A：持续造交易（下单 → 支付 → 退款 → 软删）
MYSQL_PASSWORD='MySQL口令' bash scripts/run_gen_realtime.sh

# 终端 B：持续造埋点，默认 200 QPS
bash scripts/run_gen_traffic.sh --qps 200
```

### 2.5 验证数据在动

等 30~60 秒（J2/J3 是 10 秒 checkpoint，数据在 checkpoint 完成时才提交），然后：

```bash
mysql -h127.0.0.1 -P9030 -uroot -e "
SELECT COUNT(*) AS dwd_rows, COUNT(pay_id) AS paid_rows
FROM dw.dwd_trade_order_detail WHERE dt = CURDATE();"
```

**预期**：行数持续增长；`paid_rows` 略小于 `dwd_rows`（不是每单都付款）。

## 阶段 4：离线 T+1 跑批

**目的**：从 MySQL 抽出某一天的数据，在 Hive 里算出 DWD/DWS/ADS。

**前置**：阶段 0.5 完成；MySQL 里这一天数据已定型。

```bash
export MYSQL_PASSWORD='MySQL口令'
bash scripts/run_offline_t1.sh --dt 2026-11-25
```

不传 `--dt` 默认跑昨天。

**预期**：依次打印 `ods.order_info` / `ods.order_detail` / 维表 / `dwd_payment_detail` / `dwd_refund_detail` / `dwd_trade_order_detail` / `dws.trade_1d` 的分区行数，最后打印一行 ADS 结果（5 个指标）。

**三条铁律**：

1. **只跑已经结束的那一天**，并且跑完立刻对账（阶段 5），中间不要继续造数——实时侧还在增长，对账会永远对不上。
2. **可重复跑**：每个 `dt` 分区 `INSERT OVERWRITE`，重跑会覆盖，不会重复累加。
3. **按事件日切片**：支付按 `pay_time`、退款按 `refund_time` 落到当天分区。某天的退款如果发生在次日，不会出现在前一天的离线分区里（D27）。所以离线只能对「实时链路启动日之后、且当天已完全结束」的日期对账。

**失败时**：最上面会报缺 `MYSQL_PASSWORD` 或缺 JDBC jar；Spark 报时区错，检查脚本是否带了 `-Duser.timezone=Asia/Shanghai`（脚本已内置，不要手工裸跑 `spark-submit`）。

## 阶段 5：对账

**目的**：把 Hive 的离线结果和 Doris 的实时结果按 5 个交易指标逐项比较，差异写回 Doris。

**前置**：阶段 4 刚跑完同一天；Doris 实时链路一直在跑。

```bash
bash scripts/run_reconcile.sh --dt 2026-11-25
```

**预期**：打印 5 行结果并写入 `dw.ads_reconcile_diff`：

```text
stat_date   metric        realtime      offline       diff   rate    status
2026-11-25  order_cnt     603           603           0      0       PASS
2026-11-25  pay_cnt       589           589           0      0       PASS
2026-11-25  pay_user_cnt  564           564           0      0       PASS
2026-11-25  pay_amt       1611590.98    1611590.98    0      0       PASS
2026-11-25  refund_amt    153930.96     153930.96     0      0       PASS
```

**判定规则**（详见 06-数据质量与对账 6.2）：

| 情况 | 结论 |
|---|---|
| 笔数 / 人数类，`diff_value != 0` | FAIL（阈值 0） |
| 金额类，`diff_rate < 0.1%` | PASS |
| `offline = 0` 且 `realtime = 0` | PASS |
| `offline = 0` 且 `realtime != 0` | FAIL，`diff_rate` 为 NULL |

`diff_value = realtime - offline`。

**可对账的日期**：`>= 2026-11-25`（实时链路启动日）。更早的日期实时侧没有数据，不具可比性。

**失败时**：

- 先确认离线是不是跑的是同一天，以及跑完之后有没有继续造数；
- 笔数对不上先查 DWD 当天行数，再查 `dwd_dirty_record`；
- 历史退款缺失是口径限制（D27），不是 bug。

## 阶段 6：冒烟验证

**目的**：改完某个 Flink SQL 后，用最小数据证明它算得对。

| 脚本 | 造什么 | 断言什么 |
|---|---|---|
| `smoke_j1.sh` | 插一条订单再删除 | `ods_order` 收到 `op=c`，删除后收到 `op=d` |
| `smoke_j2.sh` | 一单 + 支付 + 退款 + 软删 | 四组列依次写入且互不覆盖，退款只算成功的 |
| `smoke_j3.sh` | 一单两商品 + 支付 + 成功退款 | 三张 DWS 的笔数与金额都等于造的数量 |
| `smoke_j4.sh` | 4 条埋点（含非法字段） | 合法入 `dwd_traffic_detail`，非法进 `dwd_dirty_record` |
| `smoke_j5.sh` | 6 条埋点 | 流量 DWS 与 `uv` 正确 |
| `smoke_j6.sh` | 一单 + 支付 + 埋点 | 三张 ADS 有数且口径正确 |

跑法：`bash scripts/smoke_j2.sh`（各脚本开头会打印自己的断言）。

## 阶段 7：排障

| 现象 | 先执行 | 说明 |
|---|---|---|
| 不知道作业死没死 | `bash scripts/check_flink.sh` | 看 8 个作业状态 |
| 作业 FAILED | `bash scripts/last_job_error.sh` → `job_stack.sh` | 先看 `Caused by` 链 |
| CDC 相关报错 | `bash scripts/cdc_stack.sh` | 只看 cdc/debezium 调用栈 |
| 报错分不清新旧作业 | `bash scripts/job_timeline.sh` | 对比作业开始时间 |
| 插入后 Doris 查不到 | 等 10~12 秒；再查 label 报错 | 2PC 在 checkpoint 完成才提交；`Label Already Exists` 见 E19 |
| WSL 重启后全挂 | `bash scripts/check_env_after_reboot.sh` | 按输出逐项拉起，再回阶段 2 |
| 支付笔数少了 | 查 `dwd_dirty_record` + E31 | 历史踩坑：`sequence_col` 导致部分列更新被丢弃 |
| 文本值比较不上 | 打印长度看是否右补空格 | Doris MySQL 协议会把 VARCHAR 补到列宽，读出来要 `strip()`（E32） |
