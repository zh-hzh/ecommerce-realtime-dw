# 电商交易实时数仓

## 一、一句话自述

围绕电商交易域（下单 → 支付 → 退款 → 履约），用 Kafka + Flink SQL + Doris 搭一条秒级实时链路，同时用 Spark + Hive 保留 T+1 离线链路，**两条链路算同一套指标并互相校对**，输出差异率与数据质量报告。

## 二、业务问题

- **谁看**：运营、商家、财务。
- **看什么**：当日支付 GMV、支付转化率、退款率、TOP 商品、分省销量。
- **多快看到**：运营看板要求分钟级（目标 P99 < 5 秒）；财务结算要 T+1 精确数。
- **矛盾点**：实时链路快但可能有误差（迟到、重复、状态乱序），离线链路慢但准确。项目要回答的核心问题是——**实时的数可不可信，差多少，差在哪**。

## 三、项目边界

### 做什么

| 项 | 内容 |
|---|---|
| 实时链路 | MySQL binlog + 埋点 → Kafka → Flink SQL → Doris → 看板 |
| 离线链路 | MySQL 抽数（Spark JDBC，不经过 Kafka）→ Hive → ADS |
| 一致性 | 实时与离线同口径指标对账，输出差异率与差异明细 |
| 数据质量 | 5 类规则校验，脏数据旁路落表 |
| 维度建模 | DIM / DWD / DWS / ADS 四层落地，含累积快照事实表 |

### 明确不做

- **不做湖仓**：不引入 Paimon / Iceberg，环境里没有，且偏平台开发方向。
- **不用 DataStream**：以 Flink SQL 为主，不写 Java 流处理作业。
- **不做业务系统**：不写下单 API，交易数据由生成器按状态机推进。
- **不做多租户与权限体系**：Doris 权限只做基础账号隔离。
- **不追求 PB 级规模**：压测是把链路压到有意义的量级，不是为了数字好看。
- **不做推荐 / 算法**：只做统计类指标。

| 检查 | 命令 | 结果 |
|---|---|---|
| Doris 版本 | `mysql -h127.0.0.1 -P9030 -uroot -e 'select @@version_comment'` | `doris-3.1.4-rc02-7f5ba43de6` |
| Doris BE 存活 | `curl 127.0.0.1:8040/api/health` + `SHOW BACKENDS` | `{"status":"OK"}`；`isAlive=true` |
| Kafka KRaft | `grep -E 'process.roles\|controller.quorum' kafka/config/kraft/server.properties` | `broker,controller`；`1@127.0.0.1:9093` |
| Flink 连接器 | `ls flink/lib \| grep -E 'cdc\|doris'` | `flink-sql-connector-mysql-cdc-3.7.0-1.20.jar`、`flink-doris-connector-1.20-25.1.0.jar` |
| HDFS | `ps` + `curl 127.0.0.1:9870` | NameNode、DataNode 在跑，HTTP 302（正常跳登录） |

**四条环境约定：**

1. Doris 的 `priority_networks` 固定为 `127.0.0.1/32`。原因是宿主 WLAN 是 DHCP，IP 变过一次，FE 元数据登记旧 IP 后会卡在 UNKNOWN。绑定回环后与宿主 IP 变化解耦。
2. 浏览器访问 Doris 用 `http://127.0.0.1:8030`，**不要用 localhost**（会先解析到 `::1` 然后超时）。
3. Kafka 用 KRaft 单节点（`process.roles=broker,controller`），broker `9092` / controller `9093`，ZooKeeper 服务已停止并 `disable`。监听统一绑 `127.0.0.1`，与 Doris 同理。
4. 绑 `127.0.0.1` 不影响消费：所有客户端（Flink、spark-submit、DBeaver）都跑在同一台 WSL 里。只有需要从 Windows 宿主直连 Kafka 时才要改 `advertised.listeners`，本项目不需要。

## 八、验收标准

项目视为"可讲"，需同时满足：

1. 实时链路能从 Kafka 持续消费并写入 Doris，看板有数且延迟可测。
2. 离线 T+1 链路能重跑，同口径指标与实时可对账，输出差异率。
3. 注入的 5 类异常全部被质量规则识别：拦截/兜底类落脏数据表，重复与乱序类落到计数指标。
4. 压测有报告：QPS、延迟分位、checkpoint 大小、反压情况。
5. 表结构、指标口径、关键决策都有文档，能对着文档讲 10 分钟。
